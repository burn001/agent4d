# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/) (0.x until a stable 1.0).

## [Unreleased]

## [0.7.0] - 2026-10-30

### Fixed
- The camera no longer zooms in and back out at every cycle of an autonomous loop. When one `claude -p` cycle ended, the fit dropped it and closed in on the launcher and runner, then pulled back as soon as the next cycle appeared in the same place a few seconds later. The fit now keeps the last cycle's place while its launcher is still active. The launcher also keeps its place next to the main session instead of jumping around it (with its runner, cycles and loop board) whenever an older sibling left. Flow, Planet and voxel, 3D and 2D.
- The camera no longer twitches when the loop board sits next to the launcher, runner or cycle nodes. The board is fixed in the world, so its on-screen box grows and shrinks as the camera moves; nearby labels stepped aside or hid to avoid it, and because the auto-fit frames labels too, every such step moved the camera, which moved the board box again. The auto-fit now places labels as if the board were not there, while the labels you see still avoid it. Flow, Planet and voxel, 3D and 2D.
- After `/clear` in a session that was watching an autonomous loop, the new main session again takes over the old session's unfinished work: the launcher it had adopted, the runner, the running `claude -p` cycle with its subagents, and open Monitors now move under the new main, and the old main fades out as a past main once nothing live is left under it. Two causes: the new transcript first gets only carried-over metadata records and the `/clear` marker a few seconds later, so a server that picked the session up in between never checked for `/clear` again; and a launcher the old main had itself adopted could not be adopted again under the same id. The check now repeats until the head is complete, and the new main adopts launchers that the previous sessions of the same `/clear` chain were running (live, replay and the all-projects view agree).
- Loop board, for real this time: the done/total count no longer spills out of the board and gets cut off (for example `155/161` on a 156-axis queue showed as `155` with `/161` clipped). The far-away compact board drew the count at more than four times the text size next to the source glyph, which only fits one or two digits; so it broke whenever the camera was far enough for the compact board (almost always on a phone, sometimes on desktop) and looked fine up close, which is why the 0.6.0 phone fix seemed to come and go. The count is now sized from its number of characters (no measuring, so it is the same however the fonts load or the board is scaled), the compact board drops the glyph when the count is long, the small `✓n`/`+n` marks are hidden in the compact board, and the board uses the same UI font as the rest of the screen instead of an undefined font variable. Flow, Planet and voxel, 3D and 2D.
- A launcher replaced by a new one (the loop was stopped and started again, including a launcher adopted from a previous session) now leaves the screen like any other finished node when *Show finished* is off. It stayed for hours because the job read from the runner output file (`files` in `jobs.json`, for example *Autonomous loop*) was left running under each earlier runner when the file moved to the next runner or launcher. Those jobs are now closed as done when the file changes owner, and the same job continues under the new owner. Flow, Planet and voxel, 3D and 2D.

## [0.6.0] - 2026-10-29

### Changed
- Background music: every release from v0.6.0 carries all 22 tracks, and the README now downloads them from the latest release (`gh release download --pattern "*.mp3" --dir web/assets`, no tag) instead of v0.1.0, which only had the first 12. The README also gets a tagline: *Visual Companion for Lonely Vibecoders*.
- The plan board is now the **loop board**: one board beside an autonomous loop's launcher (it picks the axis), showing the axis queue (done/total, current axis with its phase bar, next axes) and the current axis phases with the cycle that closed each one; the large card lists every axis with its design doc and remaining phases. It is on by default (⚙ → Loop board, `?loopboard=1|0`); an old saved plan-board setting is ignored. It appears only for that loop layout and does nothing elsewhere.
- Flow nodes have new shapes. The main agent is now either a reactor core (a session-coloured hexagonal frame with a floating polyhedral core, two gyro rings and six pillars that fill with context use) or a data-band column (a glass hexagonal column where context rises like liquid, with bands scrolling the agent's real recent tool names; while a tool runs the middle band shows it in amber). Which one a main gets is fixed by its id, so it stays the same after reload, in replay, in the archive and in 2D; several live mains on one island alternate. The separate context ring around the main is gone, since the body shows it.
- Sub-agent kinds now differ by silhouette: subagent hexagon, workflow agent cut-corner hexagon with a triangle mark, `claude -p` two-tier hexagon, background command square terminal (its front shows the latest output lines up close), Monitor round puck with ripples. Launchers, job chips and detached-process rigs keep their shapes. Status colours, thinking particles and the tool spinner work the same on every shape; each silhouette is one instanced mesh.
- Your console in Flow is now a holographic console desk: a half-moon desk with a projector fan and a floating screen that shows your last message and its status directly (the separate label above it is replaced by a small "Me" badge only when the screen is too far away to read). Sending flashes the keys and lifts glyphs to the screen before the gold beam goes to the main; a question raises a gold "?" card. Flow 2D draws the same desk, reactor, column and silhouettes.

### Added
- Main-agent turns that the user did not start are now shown. A scheduled task (such as an hourly report) shows a small clock beside the main that rings, sends a light into the main and wakes it, with a `⏰` ribbon of the prompt's first words; a Monitor event sends a purple packet from that Monitor to the main with the output line riding along (`◎`); a background job finishing sends a result packet from that subagent or command to the main and leaves a `✓`, `✕` or `■` badge. If the source node has already left or is hidden, only the main side is drawn. Works in Flow, Planet and the voxel office (a desk clock, notes flying to the lead's desk and chips), 3D and 2D, live and in replay. The live panel tags scheduled turns `Scheduled` and adds the Monitor output line. These never touch your console or the voxel client screen, so they are not mistaken for your messages.
- Voxel office: each project's name is painted on its office floor as a stencil — in front of the desks between the portal and the bell (the first office of each building in the all-projects view, the root office in a single session), using the same name as the building label (or the session's working folder). Bold stencil letters with bridges, worn and scratched paint (same pattern for the same name), faded yellow paint in dark theme and dark grey ink in light theme; long names wrap to two lines or are shortened, the selected project's stencil is a bit stronger and other projects fade out with their buildings. Works in 3D and the 2D floor plan; ⚙ Voxel row `Floor name: on/off` (default on, `?stencil=0|1`).
- Voxel office workers are now about half women: their own hair styles (long, ponytail, twin tails, braid, bob, bun, bangs, long curls, pixie, hair pins and headbands), narrower shoulders and a waistline, and clothes that keep the class rule — leads in a blouse and jacket with a skirt or trouser suit, scarf, bow, brooch or necklace and pumps or loafers; subagents in knits, dresses, skirts and leggings as well as the casual set. Skirts hang from the hips so the legs walk as before. No worker is bald any more.
- Planet: parent–child links now come in two looks that take turns about every 90 seconds with a short crossfade (it waits until packets in flight have landed): a **laser link** — a thin beam between small dish antennas at the edge of each node's orbital system, whose pulse rhythm shows the status (rapid while working, a ping every 2 s when idle, beam off with a dotted guide when done, broken red on error, steady grey when stopped; `claude -p` gets a gold double beam) — and an **orbit resonance arc** — a quarter arc around the parent that ends at the child, brightest at the child (fast glow while working, dotted when done, red throb on error; `claude -p` gets a gold dotted arc around its own focus). Nodes stay where they are. Packets ride both (straight along the beam, or a short curved spoke), exits still reel in from the child end, and same-file conflicts show as two beams meeting in a flare or two outer arcs crossing (3D). Works in 3D and 2D, live, replay and archive. Choose in ⚙ (`Planet links: Alternate / Laser / Orbit rings`, shown only in Planet), with `?plinks=rotate|laser|orbit` for one visit, or `agent4d ctl plinks rotate|laser|orbit`; the legend shows the current one.
- Voxel office workers now dress by class and look different from each other: leads wear formal suits (shirt with tie, bow tie, scarf or turtleneck, dress shoes, a slightly bigger, squarer build) and subagents casual clothes (T-shirts, hoodies, sweatshirts, cardigans, polos, flannels with jeans, shorts, chinos or joggers, sneakers, caps, beanies, headphones, backpacks); operators keep the hi-vis vest and guests a long coat. Hair style and colour, skin tone, glasses, beards, height and shoulders vary too, chosen from the node id so the same agent looks the same after reloads, in replays and in 2D, and people in the same room avoid identical looks. The subagent kind colour moved to a chest logo, cuffs and cap (pocket square for leads); session colours on badges and vests are unchanged.
- Planet: subagents and `claude -p` sessions are now drawn as a small core inside one of several orbital designs, assigned per node at random but deterministically (the same node gets the same design after reloads, in replay, from the archive and in 3D and 2D). Subagents use six designs (faceted rock belt, crystal shard crown, drone squadron, orbital station, folding-wing satellites, scattered ring arcs); `claude -p` uses four (pocket star system, docking capsule, wormhole window, tool-call cassette). Siblings under one parent take different designs until the list runs out. Each design reacts to state: faster and brighter with tool-call sparks while working, slow and dim when waiting, a tidy pose when done, a red pulse on error and frozen grey when stopped. The cassette's cards show that node's own tool calls, so it does not repeat the launcher's cycle ring. Parts are drawn with scene-wide instancing and distance LOD. The detail popup names the design.
- The sound settings popup has Music and Effects on/off toggles next to their volume sliders. The top-bar sound button stays the master switch; turning only music off fades it out while effects keep playing (and the other way round), both can be off with the master still on, and the choice is saved (`ccviz.sound.parts`) so reloads, replay/live switches, resuming from pause and autoplay unlocks do not turn the switched-off part back on. Music is disabled when there are no music files. `agent4d ctl music on|off|toggle` and `ctl sfx on|off|toggle` do the same remotely; numbers still set volume.
- With music switched off, the popup's now-playing box strikes the track name through and says music is off; playback and track chips are dimmed but still selectable and apply when music is turned back on. On narrow screens and in 2D the popup now has an opaque background so the panel behind it no longer shows through.

### Removed
- The general plan board: to-dos (TodoWrite), task lists (Task), approved plans (ExitPlanMode), workflow steps and checkbox Markdown are no longer gathered into plan boards, and the plan files / plan sources / automatic plan discovery and the `agent4d plan` command added during this cycle are gone. Plan documents are not managed the same way from project to project, which kept causing trouble.

### Fixed
- Loop board on phones: the board text no longer looks too large for the board and gets cut off. Mobile browsers enlarge text by their own font-size setting (Chrome on Android's text scaling, Safari's landscape text inflation) without enlarging the fixed-size board, so the board now opts out of that adjustment; it already scales its text with the board by camera distance. The large card and other UI still follow the setting, and desktop is unchanged.
- Close-up camera (following a node, focusing a node, Follow my prompts) in every view, 3D and 2D: the camera no longer twitches every time something small changes on screen — a tool panel opening or closing, a node going idle or busy, a label or badge appearing, a small size change. The close-up framing is now held inside a dead band measured as a share of the screen, so only a real change moves it: the framing widens at once when something would be cut off, and tightens only after the looser framing has lasted two seconds. Close-ups also stop reacting to measured label room. Dragging and the wheel still take over as before.
- Voxel office (3D and 2D): a close-up no longer follows each step of a walking character. It frames where the characters are going (their desk, the station or lounge spot they are walking to, or their seat while they leave), so the camera moves once, smoothly, when someone heads somewhere new and then waits for them to arrive.
- Flow 2D (and Planet / Voxel 2D): focusing a node with `agent4d ctl focus` or its detail card could leave the camera over an empty island floor, because the filtered layout moved that node right after the camera arrived. The 2D camera now re-aims for a few seconds when the focused node moves.
- All-projects view: after a `/clear`, one autonomous loop could show two launchers — the old session's launcher handed over next to the new main (now idle) and the copy the new main adopted for the newer cycles (running). When the new main has adopted the launcher, the old one is no longer handed over, so only one launcher is shown.
- Flow and Planet 3D: plan boards were always drawn on top, even over nodes, flow lines and hologram panels that are nearer to the camera. The board now sits under the 3D canvas and the scene cuts a board-shaped window at the board's own depth, so anything in front covers it and anything behind is hidden by it; the board text stays sharp, and clicking the board still opens the large card. The window follows the board's own plane pixel by pixel, labels, speech bubbles and effect ribbons behind the board are cut where the board covers them (those in front stay whole), the soft board shadow is drawn in the scene again, and the board area no longer turns black while the context-noise effect is on (applies to the loop board).
- All-projects view: an autonomous loop handed over across a `/clear` (launcher → runner → `claude -p` cycles and their subagents) was still hidden behind a lone main node. The server already moved the launcher next to the new main, but the browser decided its visibility from the old main's session (now recent) instead of the new spawner, so the whole loop faded with the old main (the voxel office, 3D and 2D, had the same rule in its own campus layout and is fixed too). Clicking that loop's plan board also opened the large plan card for the hidden old main, which closed at once; the board now belongs to the new main and the card opens. A `/clear` made through Remote Control was also missed: the new session starts with the queued prompt and about 120 KB of tool and skill listings before the `SessionStart:clear` hook record, which fell outside the 96 KB head read, so nothing was inherited and the loop dropped out of the view entirely. The head is now read further (up to 1 MB) until the `/clear` marker window has been seen.
- All-projects view: when the server started after a `/clear`, an autonomous loop launched from the session before the `/clear` (launcher → runner → `claude -p` cycles) was hidden entirely, because the old main was attached as a recent root and the "launcher still running" rule only applied to roots the server had seen live. It now shows while the launcher runs, next to the new main, regardless of when the server started.
- Voxel office workers (3D and 2D) no longer stand on top of each other at the pantry, facilities or the lounge cabinet: each facility has numbered spots taken in arrival order (pantry 6, toolbox/board/terminal kiosk/bell 2 + 3 waiting spots, monitor wall and portal 3 + 3, lounge cabinet 7), workers who find them full work or idle at their own desk, a finished worker held at its desk walks to its new desk after a relayout, and a light separation step keeps walkers from passing through each other without leaving their route. `?mock=1&crowd=1` shows six workers going for coffee and to the same facility at once.
- The usage-limit gauges no longer disappear after a server restart while the usage endpoint answers 429: the last successful values in `usage-cache.json` are read as a seed whatever their age and shown dimmed as stale with the error. A 429 now follows `Retry-After`, or backs off 2 → 4 → 8 … up to 30 minutes, and returns to the normal interval on success; the back-off and last attempt time are shared through the cache file so the server, the CLI and `limits --watch` do not call on top of each other.

### Changed
- Background music is now picked from a pool per view: Flow plays intense coding tracks, Planet cosmic ambient, Voxel café and office music from calm to boisterous. Ten new tracks (22 in all); each track can sit at different activity levels per view (`views` in `bgm-tracks.json`). Switching views in Auto crossfades to that theme's track, an empty level falls back to the whole list, and the track picker lists the current view's tracks first with the rest under Other themes.
- With Show finished off, every kind of node except the main session now leaves the view once it ends, job nodes included: normal endings (done, stopped) after 2.5 s as before, and endings with a problem (errors, jobs that failed with rc ≠ 0) after staying visible for 10 minutes, set by `errorLingerSec` in `config.json`, per job set by `failLingerSec` in `jobs.json`, or per visit by `?errLinger=<seconds>`. Finished jobs no longer stay on screen for as long as their owner (a long-lived Monitor or collector) runs, and Voxel's job cards follow the same rule. A node with a child still working stays, and the count starts when the last child ends; hidden nodes count toward the `N finished hidden` chip.
- Voxel (3D and 2D) now follows the same rule for its staff and machines: with Show finished off, an agent that ends with an error stays at its desk, still shown in red, for the error linger time (10 minutes by default) and only then walks out the door, and an agent whose child is still working stays until the child ends; normal endings still walk out right away. The decision uses the same check as Flow and Planet, so no Voxel-only timer is involved. With Show finished on, Voxel behaves as before.

### Added
- Voxel office workers now think and talk in little bubbles: thought clouds for inner monologue (thinking, idling, coffee, stuck, tired at 70/90 % context, late nights, watching a long command) and speech bubbles for what they say out loud (starting a tool, results, push, CI, database, ssh, tests, the user's requests, questions and denials, reports, file clashes, arriving and leaving). 73 situations with about 1,930 pre-written lines each in English and Korean, shuffled per worker so lines do not repeat, sometimes mentioning the real file, command or test count (redacted values only, none in minimal privacy). At most 6 on screen, nearest and most important first, hidden when far away, thinned at 8× replay and above. Toggle in ⚙ (`Thought & speech bubbles`), `?quips=0|1` or `agent4d ctl quips on|off`. Voxel 3D and 2D only.
- `::agent4d` protocol lines accept `started` (aliases `startedAt`, `started_at`): when the job really started. The job node's start time takes this value, so a collector that attaches late or a server restart that re-reads the file no longer resets it to the time the line was read.
- Documented the pattern for remote jobs that run outside any Claude Code session (a batch on another host): a collector on the project side, which alone talks to the remote host, appends protocol lines to a local untracked file, and a rule-less `jobs.json` set with `files` (owner `main`) turns them into a job node under the project's main session. Agent4D only reads the local file and needs no SSH, credentials or new port. The bundled example set now reads such a collector file instead of Monitor relay lines.

### Fixed
- Signal degradation in the all-projects view now follows only live sessions' current context. A past main session or the session left behind by `/clear` on the same island no longer keeps the island degraded at its old, higher level while the context pill shows the new value; after `/clear` the island clears with the same sweep as a compact.

## [0.5.0] - 2026-10-28

### Added
- Long jobs started outside Claude Code (a measurement run launched with `Start-Process`, a detached batch script) can now be shown next to their project. Register one with `agent4d job add --log <file> [--pid N] [--pattern RE] [--end <marker file>] [--expect 2h]` (the PID is found from the log path when omitted), which writes one small descriptor per job to `<state folder>/jobs/`. The server tails the log and draws the job as a job node under the project's live main session, with `n/total` progress (any `12/40`-style counter by default, or your regex), rate and time left on the floor progress strip, or elapsed time against the expected duration when the job prints no progress. It ends when the marker file appears (done), the process is gone (done, or failed after a Traceback/error line or a missing promised marker), and the running server removes descriptors 12 hours after their job ended. Live only; `agent4d job list|find|rm|prune`.
- The auto camera now stays on a git action until it is done. When an agent starts a commit, push, pull, fetch, clone, merge, rebase, tag, PR create or PR merge, the camera frames that agent, its tool panel and label, and the remote-repository prop (the portal above the island in Flow, the satellite orbit in Planet, the dispatch pad in Voxel), and keeps it there until the call returns and the effect's afterglow has faded (3.6 s, shorter at fast replay speeds), then eases back. In Follow mode the tour pauses on that agent. The camera chip reads `git push` meanwhile. Manual control, an open details popup, Follow my prompts and the project or session filter still win; read-only calls and CI waits are not held, a hold ends after 20 s without a result, and actions that arrive while catching up, in a server batch, or at 8× replay and above are skipped. Flow, Planet and Voxel, 3D and 2D.
- Long-running commands carry a `meta.run` record for the viewer: while a foreground Bash/PowerShell call is open, the agent that made it gets `{kind:'fg', tool, since, lastOut, staleAfter, buffered}` (the oldest open call, cleared when it returns); background shells and detached processes get `{kind:'bg', since, lastOut, staleAfter, buffered}` plus `ended` and `rc` when they finish. `staleAfter` is the same adaptive quiet threshold as detached processes (at least 2 minutes) and `buffered` flags a command that has printed nothing yet and probably will not until the end, with the reason in `bufferWhy`: `python` (a Python run without `-u`/`PYTHONUNBUFFERED`), `pipe` (the last pipe stage holds everything until its input ends: `tail` without `-f`, `sort`, `wc`, `uniq -c`, PowerShell `Select-Object -Last`, `Sort-Object`, `Measure-Object`; `head` is not counted because it passes lines through at once) or `devnull` (output discarded or captured: `> /dev/null`, `Out-Null`, `X=$(…)`). Heredoc bodies, here-strings and quoted `|` are ignored. Updates that only move `lastOut` are sent at most every 5 seconds; replays rebuild the same record.
- Progress counters now also come from foreground shell output: `n/total`, `n%`, tqdm bars and `::agent4d` protocol lines printed by a long foreground command (live) become a Progress job under the agent that ran it, and the job ends when the call returns.
- Background shells that send their output to a log file (`> run.log 2>&1`, `| tee run.log`, `Tee-Object`, `Out-File`) now read that file as a second output stream of the same node (live only), so the panel, progress counters and quiet detection work even though the task output file stays empty.
- Long-running shells no longer look like they are resting. Nodes running a command show small tags `running 3:42 · quiet 2 min | stale 4 min · output buffered? · rc N` (elapsed switches to whole minutes after 10 minutes; the buffered tag's tooltip explains why: `python -u` or `PYTHONUNBUFFERED=1` for Python, "the last pipe (tail etc.) holds the output until it finishes", or "output is being discarded"), an open shell panel shows elapsed time in its header and a progress ring after 30 seconds, a background shell's output panel stays as a small one-line state with elapsed time instead of folding away, running shells keep their labels (the three longest first), they look busy instead of idle (stalled ones turn stall orange), the auto camera gives them a bonus that grows with elapsed time, and the inspector gets a running-shell section (elapsed, last output, buffering guess, stall against its threshold, rc). Flow, Planet and Voxel, 3D and 2D, live and in replays (replays use the replay clock).

### Changed
- Special-interaction effects in 3D Flow are now readable at the default camera distance. Lines are drawn as 2 px round-capped strokes (3 px for the most active, focused or camera-target agents) instead of WebGL's fixed 1 px lines; test scoreboards, loop progress bands, database cylinders and remote tunnels moved from the agent's height (where the tool panels covered them) to the floor around the agent; small stations of the most active agents grow until they are at least 48 px wide on screen (up to 3×); the GitHub portal is only drawn while a git action or a CI failure glow is running; and every effect stays at least 3 seconds after it ends (remote 1.4 → 3.0 s, database 2.4 → 3.5 s, loops 2.0 → 3.0 s).
- The same readability fixes now reach 3D Planet and the Voxel office. In Planet, test scoreboards, loop progress bands, database cylinders and remote tunnels sit on a deck below the planet, on the camera side and outside its orbits, instead of being scattered as 1–3 px dots over the planet body, its orbit rings and labels; they are drawn at 0.7× the Flow size (planets sit closer together) and the most active, focused or camera-target planets still grow them to at least 48 px (up to 3×). In the Voxel office, the facility effects of the most active, focused or hovered agents (parcels, cards, drone, antenna dots, quality-check lamps and bars) grow up to 2× when the office is small on screen while the furniture stays put, thin pieces stay at least 2 px wide (3 px for those agents), effects keep full strength for the first 60% of their afterglow (at least 3 seconds, as in Flow) instead of fading from the moment they end, and the dispatch pad's corner lights are only on during a git action or a CI failure glow.
- Plan boards are twice as large in Flow, Planet and Voxel, 3D and 2D: text, progress bar, item strip and padding all scale together. They keep their place beside the anchor node (growing right and up), still hide only when fully off screen, and label avoidance and the 3D cut-outs for nodes in front follow the new size. The close-up size cap doubles too.

- Long-running jobs in Planet are no longer the smallest thing on screen. Each job probe now carries the same status glyph as Flow (dots, play, hourglass, check, cross, exclamation) and grows with how long it has run (log scale, from 0.42 to the background-command size after two hours). A job flies a transfer track around its owner: the part already flown is a bright wake that thickens toward the probe, the rest is a faint dotted path ending at an arrival gate labelled with the time left and the ETA (`~13m · 16:32`), and the departure gate shows the start time. A job whose progress is only an estimate from `--expect` draws its wake dashed and labels it `est. 4:32 of 4:20` (or `over estimate N m`); a job with unknown ratio shows a comet tail and a lap marker (one lap per ten minutes); a waiting job shows twelve ticks filling toward its re-check time; a stalled wake cools from its tail; a finished track folds into a closed ring and fades in three seconds; a failed one breaks at the probe. Up to four unfinished jobs per owner get a track, the rest keep the old short trail. Jobs registered with `agent4d job add` are drawn as mining platforms (the detached-process rig) with a gauge above the derrick showing `n / N`, rate, elapsed time and ETA, or a dashed `96% (est.)` bar. The launcher ring now shows its recent cycles (green done, red failed, grey stopped) and the current cycle's progress instead of three carriers, and a re-armed Monitor shows one tick per re-arm (up to twelve). 2D Planet draws the same tracks, glyphs, platforms and rings; reduce motion stops the sparkles, dash flow and gate flash.

### Fixed
- Flow 3D floor stations, especially the test scoreboard, still covered node labels on the lowest tier: only the centre of each tile or line was checked, so tiles enlarged to the 48 px screen minimum overlapped label text while their centres sat just outside. Tiles are now checked by their on-screen radius and lines as whole segments, and the score badge and other station text fade to 20% where they cross a node label (2D Flow and Planet badges too).
- An external job's progress band covered that job's own label (Flow and Planet). Band cells and lines that fall inside a node label are now drawn at 12% so the label stays readable.
- Right after opening the page an external job had no progress band until its next progress event (up to a minute), because the snapshot carries no band. The band is now seeded from the job's own progress when the node arrives.
- A finished external job lost its label in close-up once it had ended more than ten minutes ago. Job nodes close to the camera (body at least 4 px on screen) are now label candidates whether or not they have finished.
- Gauges of neighbouring platforms could sit on top of a node label in Planet; labels now move out of the way of gauge panels.
- 3D special-interaction effects ignored the system "reduce motion" setting (test failure shake, pass sparkle and other motion kept running); they now follow it like 2D does.
- Planet never read the system "reduce motion" setting at all, so neither its special-interaction effects nor its own planet motion (spin, orbits, sparks) followed it; it now does, like Flow. The Voxel office's special-interaction effects follow it too: drone rotors, flowing cards and parcels, antenna dots, blinking lamps and test sweeps stop and show a still state.
- Background shells whose session ended first no longer stay running or stale forever. Claude Code writes the closing `[exited with code N]` line, so when the session that started a task ends before it (a headless `claude -p` run finishing its turn, a killed session, a reboot), no marker or notice ever arrives. The server now treats the session as ended when its transcript closes with a `cost-state` record (not the one written by `/clear`, whose process keeps running) or, with no such record, when the session's process record in `~/.claude/sessions` is gone or its pid is dead (only for the `cli` and `sdk-cli` entry points, after 10 seconds without the record and 30 seconds of a quiet transcript). Its open background shells then end as stopped, reason `session-end` ("Cut off when its session ended (exit code unknown)"), at the later of the session's last record and the last output; a marker or notice that still arrives afterwards wins. Live and replay use the same rule; a session whose process is alive is never cut, however quiet.
- `window.__ccviz` lost `director`, `onEvent`, `panel` and the sound handles: a comment added with the event queue swallowed the rest of that line (headless checks and the media script use them).
- Bursts of events no longer freeze the viewer. The server now queues each live connection: repeated `node-update`s for the same node within 100 ms are merged (last value wins, `meta` merged per key, other events keep their order), a slow connection or tunnel is written in one go after `drain` instead of piling up in the socket, and a connection that falls more than 5,000 events or 4 MB behind gets a fresh snapshot instead. The browser applies live events within a per-frame budget (about 6 ms); when more than 200 are waiting it applies the older ones without effects or sound and shows `Catching up n` on the connection chip until fewer than 50 remain, and a hidden tab catches up quietly in the background. Replays are unchanged.
- During a burst the server now tidies events before sending them, so the browser receives far fewer. When a connection gets more than 50 events per second, it switches to burst mode: events are held for 250 ms (growing to 1 s while the burst lasts), tidied by state, and sent as a single `batch` message. Updates to one node become one update, a node added and removed in the same window is dropped, short tool calls that finish in the window become one `tool-summary` line ("Tools · n quick calls") with the last call kept for the hologram, output keeps the latest tail plus a line count, text and thinking keep the latest (thinking sums its characters), and user messages, results, conflicts, cross-session messages and anything with interaction metadata are always kept in order. Events that stand for several originals carry `coalesced: n` and play no sound or packet. Burst mode ends below 20 events per second. A slow connection or tunnel collects into the same window until it drains, so it gets tidied more. The screen can lag up to about a second during a burst, but the final state is the same as applying every original event (property-tested), and reconnecting with `since` works as before. Replays and the server's event buffer keep the original events. In a test with 20,000 events, the browser received about 145 events instead of about 17,000, and the longest frame dropped from 171 ms to 57 ms in 3D and from 110 ms to 23 ms in 2D.
- Agents running a long foreground command no longer turn idle after one minute: a node with an open shell call stays active (up to the call's timeout plus a minute), live and in replays. Background shells no longer turn idle after a quiet minute either; they wait for the adaptive quiet threshold.
- Background shells whose completion notice never arrived (or was only written as a queued notice) no longer stay idle forever: the task output's closing `[exited with code N]` line ends them (0 done, 130/137/143 stopped, others failed, exit code kept), and queued notices count as notices without being shown twice.
- tqdm-style progress that rewrites one line with carriage returns now shows as one updating line in the panel and drives the progress counter, instead of every update being glued into one long line.
- A command that ran in the foreground and then moved to the background now starts at the time it was launched, not when it moved.
- The artifact layer showed far more objects in Planet than in Flow for projects with many agents: Planet's round island is larger, so its 500 targets stayed one-per-file while Flow folded them into folder groups. Both views now switch to folder groups once a project has more than 150 targets (`ART.LOD_COUNT`), whatever the island size.
- Plan boards for phase design docs now list every phase, not only the first. A run that looked at the doc in pieces (`sed -n 1,66p`, a partial Read, a `grep` of headings) only showed the phases inside that piece, and a `grep -n '단계 . 상태'` chained after other commands on another `.md` file (`git status && wc -l SUPERVISOR.md && grep …`) was dropped because its lines carry no file prefix. Partial views now merge into the known plan without removing phases they did not show, and unprefixed status lines go to the one design doc in the command.
- Phase design docs are recognised in more shapes: `## Phase N` / `Step` / `Stage` headings, numbers like `1a` or `10`, table rows (`| 단계 N | name | ✅ |`), and status lines without bold. A phase heading with no status line is listed as pending (and a later partial view without status keeps the known status). The `**단계 N 상태**: ✅/◑/⏸` form works as before.

## [0.4.0] - 2026-10-26

### Added
- Detached processes: when an agent starts a program or script in the background from a normal shell call (`nohup … &`, `( … ) > log 2>&1 &`, `setsid`, `disown`, PowerShell `Start-Process`/`Start-Job`, `start /b`, `python -m …`, a venv `python.exe`), it now gets its own node under that agent instead of the agent just looking idle. It ends on `EXIT n`/`rc=n` lines, a Python traceback, a kill command that names it, or long silence, and shows as stalled when the log stops growing for longer than its usual line gap. Protocol lines and `jobs.json` rules still win.
- Watching: when another shell call or Monitor reads or waits on that log (or its output folder), a new `watch` event links the reader to the process (peek or wait), and progress lines in what it saw count too. Replays place log lines at the times they were seen. `?mock=1` and `--demo` include a two-lane job that slows down, is checked every few seconds and finishes, plus one that fails fast.
- Planet (3D and 2D) draws detached processes as a mining rig on a small asteroid beside the agent that started it: the auger spins with the rate, slows and stutters as heat rises while its bore glows amber to vermilion, ore chunks ride one conveyor orbit per progress lane into a cargo ring around the agent (a big chunk per progress line), a hologram meter shows rolling counters, rate, longest unit time, heat and ETA (just the big number from afar), and watching shows as a waiting orbit with a probe or a scan beam, with the agent's line reading "Supervising · script · count".
- Flow (3D and 2D) draws detached processes as a standing machine beside the agent that started it: a rotor spins on top (slowly when the log stalls, with a blinking warning dot, and spins down when it ends with a green, red or grey wave), the front panel rolls one odometer counter per progress lane with a rate sparkline, heat bar and ETA (one big number from afar), and the body warms from teal through amber to vermilion as heat rises (heat haze in dark, deeper ink in light). Each new progress line pops a small tick out along the dashed spawn line, watching shows as a scan sweep from the watcher, a waiting ring around the machine and a check on the panel, the watcher's line reads "Supervising · script · count", hovering shows a small card, and the click card (every view) gets a progress-lane table plus the log path, watch count and end reason.
- Voxel office (3D and 2D) draws detached processes as a production line in the office of the agent that started it: a machine with a spinning flywheel, chimney steam and a beacon (amber when warm or stalled, red when hot or failed, green when done), one conveyor per progress lane running at the rate, a crate for each progress line that rides to a pallet stacked as a compressed tally (bundles and singles), and a forklift that carries the pallet away on a new pass or when the job ends. The progress job becomes a scoreboard above the machine with rolling lane counters, rate, longest unit time and ETA. When the agent checks the log, its character walks to the machine with a clipboard, reads the board and ticks it, or waits with arms folded (too-frequent peeks, fast replay or other rooms show a dotted look line from the desk instead).
- Remote control from the PC running the server: `agent4d ctl <command>` changes every open viewer (or one picked with `--client`) — theme, view, 2D/3D, project or session scope, what is shown, sound and volumes, music, language, camera, focus, live pause, replay, layers, weather, grid, noise, panel, timeline, popups, reload and on-screen messages — exactly as if picked in the menus (saved, or `--temp` for this visit only). `ctl clients` lists open viewers; each viewer answers with the result, and the CLI reports how many applied and why others did not (including "click the page once" for sound). Sending works only locally (loopback, no relay/tunnel/proxy headers, admin secret); remote viewers only receive. ⚙ gets "Screen name" and "Remote control: Accept/Ignore".

### Changed
- Flow 3D: the "me · user" console is now a solid terminal instead of a flat outline — a hexagonal base with a glowing ring, a neck, a screen panel tilted back with a bezel and a back cover, dark glass that lights up by state (no messages, main working, answered, asking me, interrupted) and a status light on the bezel, with the same floor shadow and dashed stem line as the hexagonal nodes. The text lines and the name tag stay as before; the gold beam and ribbon of a user message now leave from the screen.
